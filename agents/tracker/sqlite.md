# Tracker backend: sqlite (opt-in)

Implements the tracker port (`agents/tracker/port.md`) with **SQLite as the sole work-item store** when `tracker.backend: sqlite`. Agent steps invoke **`lib/dw-db.sh` only** — never freehand `sqlite3` SQL, never live `REQ-*.md` / `user-requests/` trees.

**This is not the default.** When `tracker.backend` is missing, empty, or `markdown`, agents load `markdown.md` instead. When `linear`, load `linear.md`.

---

## When to load

After config load and backend resolution (`port.md` load path + `agents/config.md` Load Config):

1. Effective backend is **`sqlite`**.
2. `sqlite3` is on `PATH` — else **hard-stop** (install hint).
3. Read `agents/tracker/port.md`.
4. Read this file (index + hard rules).
5. Run work-item ops only via `bash {skill-root}/lib/dw-db.sh …`.

Do **not** load this file for ordinary work-item ops when backend is `markdown` or `linear`.

---

## Hierarchy (authoritative)

```
{project}/.do-work/
├── work.db              — sole work-item store (URs, REQs, claims, artifacts, …)
├── evidence/UR-NNN/     — binary / UI / closure evidence only (not tickets)
│   ├── ui-evidence/
│   └── closure-evidence/
├── state/               — runtime locks only (gate-owner, final-suite, …)
│   └── gate-owner.md
├── board/               — static HTML snapshot (regenerated by /do-work board)
└── runs/                — optional local ledger telemetry (not work-item truth)
```

| Entity | Home |
|--------|------|
| Product container | project root + `dw-db ensure` (dirs + empty `work.db`) |
| UR | `urs` row; external id = slug `UR-NNN` |
| REQ | `reqs` row; external id = slug `REQ-NNN` |
| Ideate / clarifications / verify / close | `ur_artifacts` (`kind`) |
| Decisions | `decisions` table (append-only lines) |
| Calibration | single-row `calibration` (id=1) |
| Milestone cursor | `milestone_state` **per UR** (`ur_id` UNIQUE) |
| Run notes | `run_notes` rows on REQ |
| Gate locks | **local** `.do-work/state/gate-owner.md` only — **not DB** |

### Hard rules (hierarchy)

1. **No dual-write** — while `backend: sqlite`, do not treat `REQ-*.md`, `user-requests/`, `decisions.md`, `state/calibration.md`, or `state/active-milestone.md` as live work-item truth.
2. **Slugs only at the agent surface** — never invent integer PK usage in prompts/commits; `dw-db` resolves slugs internally.
3. **DB status underscore** — store `in_progress` (CLI may accept `in-progress` and normalize).
4. **Evidence under** `.do-work/evidence/UR-NNN/{ui,closure}-evidence/` only.
5. **No freehand SQL** — all work-item ops go through `lib/dw-db.sh`.

## Hard-stop template (sqlite)

When any of the following is true, **hard-stop** the phase. **Never** fall back to markdown or Linear.

| Condition | Agent action |
|-----------|--------------|
| `sqlite3` not on `PATH` | Stop: install `sqlite3` (OS package / Xcode CLT) |
| `agents/tracker/sqlite.md` missing | Stop: skill install/upgrade incomplete |
| `dw-db ensure` / open fails (corrupt DB) | Stop: repair or recreate empty `work.db` (no history migrate) |
| `PRAGMA user_version` ≠ supported (1) | Stop: unsupported schema; recreate empty DB |
| `dw-db` command non-zero for a required op | Stop with stderr; leave claims as-is (mid-flight leave-claimed) |

Hard-stop message shape:

```text
Hard-stop: sqlite tracker unusable — <reason>.
Do not fall back to markdown or Linear. Fix sqlite3 / work.db / skill install, then resume.
```

## Artifact write semantics

| kind | Write | Notes |
|------|-------|--------|
| `ideate` | append | Concat with blank-line separator; **never** touch `urs.brief` |
| `clarifications` | append | Q/A blocks |
| `open_gaps` | replace | Continue-gate machine list |
| `capture_summary` | replace | Capture rollup text |
| `verify` | replace | Full verify report body |
| `close` | replace + `closed_at` | Sets `urs.closed_at` on first successful close write (preserved on later replaces) |

---

## Claim protocol (summary)

1. **Pick:** `list-claimable` / `pick` — backlog + deps done + footprint free + no fresh active claim (stale → takeover-eligible).
2. **Claim:** single transaction — release stale active if needed, insert new active, set `in_progress`.
3. **Heartbeat:** **UPDATE** the active claim row’s `heartbeat` only (never insert a second active row).
4. **Archive:** `check-archive` / `archive-req` — proof + AC + done; release claim.
5. **Unblock:** backlog + release claim.
6. **Mid-flight backend failure:** leave claim active; resume/unblock after recovery (`port.md` mid-flight).

Stale max default: **900s** (override with `--stale-max`).

## `write_gate_state` (local only)

Deploy-gate and final-suite coordination **must not** enter `work.db`.

| Action | Path |
|--------|------|
| Claim gate ownership | Write `{root}/.do-work/state/gate-owner.md` with agent id; re-read confirms self |
| Release gate | Delete `gate-owner.md` |
| Final-suite lock | `{root}/.do-work/state/final-suite-running.md` (or milestone-scoped variant) |

This is **not** dual-write of work items — locks are runtime, same as markdown/Linear.

Do not write `.do-work/state/calibration.md` as the store while backend is sqlite.

## `migrate_markdown_to_linear` — refuse under sqlite

When effective backend is **`sqlite`**:

1. **Refuse** `migrate_markdown_to_linear` / `/do-work upgrade migrate` cutover to Linear.
2. Do **not** import markdown history into `work.db` (no markdown→sqlite migrate in v1).
3. Leave `tracker.backend`, `work.db`, and any historical markdown trees unchanged.
4. Operator who wants Linear must switch backend policy separately; v1 does not convert sqlite → Linear either.

Refuse message shape:

```text
Refuse: migrate_markdown_to_linear not applicable — tracker.backend is sqlite.
No markdown→Linear cutover and no markdown→sqlite import in v1.
```
