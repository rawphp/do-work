# Design: Do-work SQLite tracker backend + local HTML board

**Date:** 2026-08-11  
**Status:** approved for implementation planning  
**Source:** brainstorming session (markdown sprawl → local structured store + visibility; remote deferred)

## 1. Problem

do-work’s default **markdown** work-item store becomes unwieldy at scale: hundreds of peer UR/REQ documents, expensive for agents to glob/read and hard for operators to see “what’s going on.”

**Linear** as an optional sole store works for product boards but the current hierarchy (UR = Project Milestone stuffing brief/ideate/verify/close) floods project chrome and raises agent read/write cost. Fixing Linear hierarchy is a separate effort.

**GitHub Issues** map structurally to parent/sub-issue work, but are a poor high-churn agent coordination bus (claims, heartbeats, pick loops) under global agent API pressure and secondary rate limits.

Operators want:

1. **Local** sole store that is structured (not file sprawl)
2. **Human visibility** without opening a database or hundreds of files
3. **Shared integration** with existing backends (one port)
4. **Remote glance** optional later — **out of v1**

## 2. Goals

1. **New opt-in backend `sqlite`** — when `tracker.backend: sqlite`, work items live **only** in `{project}/.do-work/work.db` (no dual-write to markdown or Linear).
2. **Markdown remains the default** — unset/empty `tracker.backend` → `markdown`; existing projects and tests unchanged until operators opt in.
3. **Common integration** — markdown, Linear, and sqlite share the same tracker port: load path, op catalog, claim/deps/footprint semantics, hard-stop rules. Backends differ only in representation.
4. **Local visibility** — `/do-work board` writes a **static HTML snapshot** operators open in a browser.
5. **Greenfield from switch** — switching to sqlite starts empty; **no migration** of historical markdown/Linear work items in v1.

### Done when

- With `tracker.backend: sqlite`, an agent can complete intake → ideate → capture → verify → run (claim / deps / footprint) → status / close against `work.db` only.
- `/do-work board` produces a usable HTML snapshot from the DB (explicit regen only).
- Default markdown path still passes existing regression (`lib/tests`, conformance) without sqlite.
- Every port op name is documented in `agents/tracker/sqlite.md`.
- Config load path accepts `sqlite` and hard-stops on unusable DB without falling back to markdown.

## 3. Non-goals

- Markdown ↔ sqlite migration / import (not required; not default)
- Linear ↔ sqlite migration
- Fixing Linear hierarchy (UR = parent Issue, etc.)
- GitHub Issues backend
- Remote mirror / glance (Linear or GitHub)
- Live localhost board server or edit-in-browser
- Dual-write any backend pair
- Changing TDD-per-REQ, worktree isolation, or post-build review philosophy
- Replacing markdown as the default backend
- True distributed multi-host locking beyond single-machine SQLite transactions

## 4. Decisions (locked)

| Decision | Choice |
|----------|--------|
| Approach | **A:** SQLite sole store + static HTML board |
| Backend name | `tracker.backend: sqlite` |
| Default backend | Still **markdown** (opt-in sqlite) |
| Integration | **One port** — `port.md` + `agents/tracker/{markdown,linear,sqlite}.md` |
| Store path | `{project}/.do-work/work.db` (configurable) |
| Migration | **None in v1** — empty DB from switch forward; historical files ignored as live truth |
| Board | Static HTML; **`/do-work board` only** (no auto-regen on claim/archive) |
| Board scope | **sqlite only** in v1 |
| Remote | Deferred |
| REQ / UR ids under sqlite | Keep **`UR-NNN` / `REQ-NNN`** (markdown parity; commit `feat(REQ-NNN):`) |
| Claim atomicity | SQLite **transaction** (same port outcomes as markdown FS / Linear optimistic comment) |
| Dual-write | **Never** while backend is sqlite |
| Unusable DB | **Hard-stop** — never silent markdown fallback |
| Runtime / git | Stay local: worktrees, merges, `state/*` locks, config, optional ledger telemetry |

## 5. Architecture

### 5.1 Layout

```
.do-work/
  config.yml
  work.db                 # sole work-item store when backend=sqlite
  board/index.html        # static snapshot (regenerated by /do-work board)
  state/                  # runtime locks (gate-owner, etc.) — unchanged
  runs/                   # optional ledger telemetry — unchanged
  # user-requests/, REQ-*.md, working/, archive/ — NOT live truth when backend=sqlite
```

### 5.2 Common integration (all backends)

```
config → tracker.backend → port.md → agents/tracker/<backend>.md → named ops only
```

| `tracker.backend` | Backend file | Store |
|-------------------|--------------|--------|
| unset / empty / `markdown` | `markdown.md` | `.do-work/` files + existing `lib/*.sh` |
| `linear` | `linear.md` | Linear MCP only |
| `sqlite` | `sqlite.md` | `.do-work/work.db` + sqlite lib/CLI |

**Shared:** `agents/tracker/port.md` (op names, preconditions, claim/deps/footprint/pick rules, mid-flight leave-claimed).

**Backend-specific:** representation only (files vs Linear entities vs SQL rows).

**Phase agents** keep product logic; they must not invent raw SQL, raw Linear tools, or raw markdown paths outside the active backend file.

### 5.3 Work-item vs runtime (unchanged split)

| In `work.db` (sqlite mode) | Always local runtime |
|----------------------------|----------------------|
| URs, REQs, deps, claims, ideate/verify/close artifacts, decisions, calibration, milestone cursor, run notes | worktrees, git, `state/*` locks, `config.yml`, optional `runs/` telemetry |

### 5.4 Implementation surface

| Layer | Role |
|-------|------|
| `agents/tracker/sqlite.md` | Op sequences agents follow |
| `lib/` sqlite helpers or single `dw-db`/sqlite CLI | CRUD, pick, claim transactions — **owns concurrency**, not agent freehand SQL |
| Board generator | Read-only query → HTML |
| `agents/config.md` + SKILL | `sqlite` backend key, load path, hard-stop copy |

## 6. Data model

Single file DB; schema versioned (`PRAGMA user_version` or `schema_version` table).

### 6.1 Tables

**`urs`**

| Column | Notes |
|--------|--------|
| `id` | Integer PK |
| `slug` | `UR-NNN` unique |
| `title` | short |
| `class` | feature / … |
| `brief` | verbatim intake (primary large field on the row) |
| `created_at` | ISO |
| `closed_at` | null until closed |

**`ur_artifacts`**

| Column | Notes |
|--------|--------|
| `ur_id` | FK |
| `kind` | `ideate` \| `clarifications` \| `verify` \| `close` \| `capture_summary` \| `open_gaps` \| … |
| `body` | markdown/text |
| `updated_at` | |

v1: **one row per (ur_id, kind)** — upsert/replace or in-body append per op semantics (ideate/clarifications append rules mirror port).

**`reqs`**

| Column | Notes |
|--------|--------|
| `id` | Integer PK |
| `slug` | `REQ-NNN` unique (sequential allocate) |
| `ur_id` | FK |
| `title` | |
| `status` | `backlog` \| `in_progress` \| `stopped` \| `done` |
| `layer` | |
| `parent_req_id` | path-unit children |
| `entry_point` / `terminal_state` | path-unit parents |
| `path_milestone` | `M1` / null |
| `files` | footprint (space-separated paths/globs) |
| `size` / `priority` | |
| `criteria_approved` | |
| `closure_proof` / `suite` | |
| `body` | markdown template sections (task, AC, verification, integration, outputs) |
| `created_at` / `updated_at` | |

**`deps`** — `req_id`, `depends_on_req_id` (authoritative for eligibility)

**`claims`** — `req_id`, `agent_id`, `claimed_at`, `heartbeat`, `session`, `status` (`active` \| `released`)

**`decisions`** — append-only decision lines

**`calibration`** — single-row full body (retro replace)

**`milestone_state`** — per-UR active M + checklist JSON (path-milestone mode)

**`run_notes`** — req_id + payload + timestamps

### 6.2 Identifiers and commits

```
feat(REQ-NNN): short title

REQ: REQ-NNN
UR: UR-007
Output: path/to/primary/output
```

Branch/worktree: `req/REQ-NNN` (same family as markdown). No Linear/GitHub issue ids under sqlite.

### 6.3 Board read model

List views load slim fields only (slug, title, status, claimer, heartbeat, priority, layer, blocked). Full brief/body only on explicit drill-down in HTML if included.

## 7. Operation catalog

**No new work-item op names for sqlite.** Every op in `port.md` is implemented in `sqlite.md`.

Board generation is **not** a work-item port write op. It is a **read-only viewer command** (`/do-work board`) implemented for the sqlite backend (may use direct read-only SQL in the generator; must not mutate work items).

### Representation map (summary)

| Concern | markdown | linear | sqlite |
|---------|----------|--------|--------|
| UR | `user-requests/UR-NNN/` | Project Milestone (current) | `urs` + `ur_artifacts` |
| REQ | `REQ-*.md` paths | Issue id | `reqs.slug` |
| Claim | FS move + stamp | comment + state | `claims` + status in transaction |
| Deps authority | body header | native blocks | `deps` table |
| Hard-stop if unusable | n/a | MCP/team/status_map | corrupt/schema/lock timeout |

### Claim (sqlite)

Port semantics unchanged (optimistic, concurrent-conflict, stale, leave-claimed).

| Step | SQLite |
|------|--------|
| Pick | SQL: backlog, no active fresh claim, deps all `done`, footprint free |
| Claim | Transaction: re-check → `in_progress` → active claim row |
| Heartbeat | Update `claims.heartbeat` |
| Unblock | backlog + claim `released` |
| Archive | proof + `done` + release claim |

## 8. Config schema

```yaml
tracker:
  backend: markdown          # markdown | linear | sqlite
  sqlite:
    path: ""                 # default: .do-work/work.db (relative to project)
    board_path: ""           # default: .do-work/board/index.html
  linear:
    # existing — unchanged by this design
```

**Validation when `backend: sqlite`:**

- Resolve DB path; create parent dirs as needed via `ensure_product_container`
- Open/create DB; apply migrations for schema version
- Missing DB on first ensure → create empty schema (not an error)
- Corrupt DB or unsupported schema version → **hard-stop** with repair/recreate instructions; **no** markdown fallback

## 9. Board (visibility)

| Item | Spec |
|------|------|
| Command | `/do-work board` |
| Output | `tracker.sqlite.board_path` or `.do-work/board/index.html` |
| Regen | **Explicit only** — never auto on claim/archive/create/status |
| Backend | **sqlite only** in v1; other backends → clear error (use `/do-work status` or Linear UI) |
| Mutability | Read-only snapshot |
| Format | Self-contained HTML (inline CSS; no required external CDN) |

### Page content

| Region | Content |
|--------|---------|
| Header | project name, `generated_at`, backend |
| UR list | open URs: slug, title, REQ counts by status |
| REQ view | backlog / in_progress / stopped / done (table or columns) |
| Row fields | slug, title, UR, status, claimer, heartbeat age, priority, layer, blocked? |
| Stale banner | active claims older than `parallel.stale_threshold_seconds` |

### Status vs board

| Command | Audience |
|---------|----------|
| `/do-work status` | Terminal situation room — all backends |
| `/do-work board` | Human HTML snapshot — sqlite v1 |

## 10. Switching to sqlite (no migration)

1. Operator sets `tracker.backend: sqlite` in `.do-work/config.yml`.
2. Next work-item phase runs load path → `ensure_product_container` creates empty `work.db` + schema if missing.
3. **From that moment forward**, all work-item ops use sqlite only.
4. Existing markdown trees (`user-requests/`, backlog/archive REQ files) remain on disk as **non-live history** — not imported, not deleted, not dual-written.
5. To continue old work: finish under markdown **before** switch, or re-intake under sqlite. No automatic import.

**Out of scope:** one-shot migrate tools, dry-run importers, Linear↔sqlite bridges.

## 11. Error handling

| Failure | Behavior |
|---------|----------|
| DB missing on ensure | Create empty DB + schema |
| Corrupt / schema mismatch | Hard-stop; repair or delete DB and start empty; no markdown fallback |
| Lock timeout | Short retry; then hard-stop or concurrent-conflict as appropriate |
| Claim race | concurrent-conflict (port) |
| Mid-flight crash after claim | Leave claimed; resume/unblock |
| `/do-work board` when backend ≠ sqlite | Clear error; do not invent a markdown/Linear HTML board in v1 |
| Agent reads markdown REQ paths while backend=sqlite | Forbidden; backend file + help/status must state sole store |

## 12. Testing and proof

1. **Markdown regression** — default backend; existing `lib/tests` + conformance pass without sqlite requirement.
2. **Port parity checklist** — every op in `port.md` has a sqlite sequence in `sqlite.md`.
3. **Lib/CLI tests** — schema init, claim race (two claimants), deps satisfaction, footprint overlap, pick order, status transitions, archive.
4. **Board generator** — fixture DB → HTML contains expected UR/REQ rows and `generated_at`.
5. **No migration tests** (none shipped).

## 13. Implementation phasing (for writing-plans)

1. Config: `tracker.backend: sqlite` + `tracker.sqlite.*` + load path hard-stop rules  
2. Schema + `ensure_product_container` (create empty DB)  
3. `agents/tracker/sqlite.md` + lib/CLI: UR/REQ CRUD + list ops  
4. Claim / pick / deps / footprint / heartbeat / unblock / archive  
5. Artifacts: ideate, clarifications, verify, close, decisions, calibration, run notes, milestone cursor  
6. Wire docs in SKILL / config / help; ensure phase agents already use port load path  
7. `/do-work board` HTML generator + command stub  
8. Troubleshooting: switch semantics, “old markdown ignored,” board explicit regen  

## 14. Open risks

1. **Silent markdown reads** if an agent skips the load path — mitigate with hard-stop messaging and status/help when backend is sqlite.  
2. **Empty start feels lossy** — document switch semantics; no default migrate by design.  
3. **Board staleness** — explicit regen only; always show `generated_at`.  
4. **SQLite multi-process** — single-machine WAL + transactions; document not multi-host.  
5. **Linear still painful** for existing Linear users — out of scope; separate hierarchy redesign.
